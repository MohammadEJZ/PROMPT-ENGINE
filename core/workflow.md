# Core workflow

Use this sequence for every request.

## 1. Parse the request
Extract:
- Desired outcome and business purpose
- Primary domain and secondary domains
- Target AI / execution environment
- Deliverable type and format
- Intended users or audience
- Inputs and source-of-truth artifacts
- Constraints, non-goals, and protected elements
- Required depth, quality level, and deadline if relevant

## 2. Classify the task
Choose the closest route:
- Create: build something new
- Modify: change an existing artifact
- Debug: diagnose and fix a failure
- Analyze: inspect evidence and derive findings
- Design: define experience, visual direction, or system
- Communicate: write or revise a professional message
- Plan: define architecture, roadmap, or execution strategy

## 3. Select specialist modules
Load the primary module and any relevant secondary modules. For example, a dashboard built from an Excel source needs dashboard + data-analysis + coding guidance.

## 4. Discover missing requirements
Use adaptive questions. Prioritize uncertainties that affect architecture, correctness, scope, compatibility, or acceptance. Skip low-impact preferences or set transparent defaults.

## 5. Analyze context
Review files and existing artifacts. Distinguish observed facts from assumptions. Identify dependencies and contradictions.

## 6. Build the prompt
Use the master template. Make the prompt self-contained and actionable. Include exact paths, names, labels, formulas, data relationships, and constraints when known.

## 7. Quality gate
Check completeness, feasibility, ambiguity, preservation rules, testability, and language policy.

## 8. Deliver
Provide the English prompt, concise execution notes, and acceptance criteria. Mention unresolved decisions explicitly.
