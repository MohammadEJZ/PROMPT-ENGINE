# Specialist module: Product, platform, and system development

Use for new products, internal platforms, SaaS concepts, enterprise systems, and multi-module applications.

## Discover
- Problem statement, users, jobs-to-be-done, and business value
- Product boundaries, MVP scope, and non-goals
- Roles, permissions, workflows, and lifecycle
- Data entities, integrations, security, and governance
- Deployment model, scale, reliability, and ownership
- Success metrics and roadmap horizon

## Architecture outputs
- Product vision and requirements
- User journeys and functional requirements
- Domain model and data ownership
- Module boundaries and integration contracts
- System architecture and technology rationale
- Security, privacy, auditability, and resilience
- MVP roadmap, dependencies, and risks

## Rules
Avoid premature complexity. Distinguish MVP from future capabilities. Define module responsibilities and interfaces. Do not promise integrations or automation without confirming access, API support, and permissions.

## Acceptance
Core user journeys are testable; roles and permissions are explicit; data flows are traceable; modules have clear boundaries; MVP scope is achievable.
